# Swerve Drive

This document covers the swerve drivetrain system, including hardware configuration, the CTRE Phoenix 6 swerve API, operator controls, and tuning.

## Overview

The robot uses a **4-module swerve drive** with CTRE Kraken X60 FOC motors for both drive and steer. The drivetrain is built on top of CTRE's Phoenix 6 swerve API, using the `SwerveDrivetrain` class generated by Tuner X.

**Key specs:**
- Max speed: **4.73 m/s** (at 12V)
- Max angular speed: **1.1 rotations/sec** (6.91 rad/s)
- Drive gear ratio: **6.746:1**
- Steer gear ratio: **21.43:1**
- Wheel radius: **2.1 inches** (0.053 m)
- Module spacing: **10.375 inches** from center (20.75" wheelbase)

## Hardware Layout

### Module CAN IDs

All swerve devices are on the `"Drivebus"` CAN bus (`Robot.drivebus`).

| Module | Drive Motor | Steer Motor | CANcoder | Position |
|--------|------------|-------------|----------|----------|
| Front Left | 10 | 11 | 12 | (+10.375", +10.375") |
| Front Right | 20 | 21 | 22 | (+10.375", -10.375") |
| Back Right | 30 | 31 | 32 | (-10.375", -10.375") |
| Back Left | 40 | 41 | 42 | (-10.375", +10.375") |

**Pigeon 2 IMU**: CAN ID 2, on `"Drivebus"`. Mount pose calibrated via Tuner X: Yaw=1.066, Pitch=0.238, Roll=-0.978 degrees.

### Motor Configuration

- **Left side** modules: drive motors NOT inverted
- **Right side** modules: drive motors inverted
- **All steer motors**: inverted (true)
- **Steer feedback**: FusedCANcoder (CANcoder fused with motor encoder for maximum accuracy)
- **Drive closed-loop**: Voltage output
- **Steer closed-loop**: Voltage output
- **Slip current**: 65A (stator current at which wheels slip)
- **Steer current limit**: 60A stator

### Encoder Offsets

Each CANcoder has a calibrated offset so the wheel's "zero" angle is straight forward:

| Module | Offset (rotations) |
|--------|-------------------|
| Front Left | 0.415527488 |
| Front Right | 0.474854 |
| Back Left | 0.472900488 |
| Back Right | -0.027100 |

These offsets are determined using Phoenix Tuner X and should NOT be manually modified.

## Code Structure

### TunerConstants.java (Generated)

**File**: `frc/robot/subsystems/drive/generated/TunerConstants.java`

This file is **generated by CTRE Tuner X Swerve Project Generator**. It contains:
- PID gains for steer (kP=10) and drive (kP=0.02, kV=0.124)
- Gear ratios, wheel radius, coupling ratio
- Motor types, feedback types, closed-loop output types
- Per-module CAN IDs, encoder offsets, positions
- The `TunerSwerveDrivetrain` inner class that extends `SwerveDrivetrain<TalonFX, TalonFX, CANcoder>`
- Pigeon 2 mount pose configuration

**Do NOT edit this file by hand.** Regenerate it using Tuner X if hardware changes. See the [CTRE Swerve Project Generator docs](https://v6.docs.ctr-electronics.com/en/latest/docs/tuner/tuner-swerve/index.html).

### SwerveSubsystem.java

**File**: `frc/robot/subsystems/drive/SwerveSubsystem.java`

The main swerve drive subsystem. It extends `TunerSwerveDrivetrain` and implements the WPILib `Subsystem` interface so it works with the command scheduler.

#### Key Responsibilities

1. **Singleton access** via `getInstance()`
2. **Registers with CommandScheduler** in constructor
3. **Configures PathPlanner AutoBuilder** in constructor
4. **Operator perspective management** — applies alliance-based rotation so "forward" is always away from the driver
5. **Pose access** — `getPose()` returns either real or simulated pose
6. **SysId support** — built-in steer characterization routine for system identification
7. **Simulation bridge** — starts `MapleSimSwerveDrivetrain` in a 200Hz Notifier if running in simulation

#### PathPlanner AutoBuilder Configuration

```java
AutoBuilder.configure(
    this::getPose,                  // Pose supplier
    this::resetPose,                // Odometry reset
    this::getRobotRelativeSpeeds,   // ChassisSpeeds supplier
    this::drive,                    // Drive consumer (ChassisSpeeds + feedforwards)
    controller,                     // PPHolonomicDriveController (P=0.5 trans, P=0.3 rot)
    SwerveConstants.robotConfig,    // Mass, module config, module positions
    () -> isRedAlliance(),          // Alliance flip supplier
    this                            // Subsystem requirement
);
```

#### Operator Perspective

The operator perspective determines which direction "forward" means. When on Red alliance, "forward" is 180 degrees from Blue's perspective.

`setOperatorPerspectiveAndAdjustPose(Rotation2d)` does two things:
1. Calls the underlying `setOperatorPerspectiveForward()` to rotate field-centric controls
2. Rotates the current odometry pose by the same delta, so the robot's perceived heading stays consistent

This runs on every `periodic()` while disabled (to handle alliance changes) and in `teleopInit()`.

#### Public API

| Method | Description |
|--------|-------------|
| `getInstance()` | Singleton access |
| `applyRequest(Supplier<SwerveRequest>)` | Returns a Command that continuously applies a swerve request |
| `getPose()` | Current robot pose (real or simulated) |
| `getChassisSpeeds()` | Current chassis speeds |
| `resetPose(Pose2d)` | Reset odometry to a specific pose |
| `bigResetPose()` | Reset odometry to (0,0,0) |
| `getRobotRelativeSpeeds()` | Chassis speeds from module states via kinematics |
| `sysIdQuasistatic(Direction)` | SysId quasistatic characterization command |
| `sysIdDynamic(Direction)` | SysId dynamic characterization command |
| `setOperatorPerspectiveAndAdjustPose(Rotation2d)` | Set operator perspective with pose correction |

## Operator Controls

Defined in `ControlBoard.java`. The driver uses a PS5 controller on port 0.

### Drive Request

The default drive command uses `SwerveRequest.FieldCentric`:

| Setting | Value |
|---------|-------|
| Translation deadband | 5% of max speed |
| Rotation deadband | 10% of max angular speed |
| Drive request type | Open-loop voltage |
| Steer request type | Position (closed-loop) |
| Desaturate wheel speeds | Enabled |
| Perspective | Operator perspective (alliance-aware) |

### Joystick Mapping

| Input | Action |
|-------|--------|
| Left stick Y | Forward/backward velocity (60% of max) |
| Left stick X | Left/right velocity (60% of max) |
| Right stick X | Rotation rate (80% of max, squared for sensitivity curve) |
| Right bumper (hold) | Precise mode: 25% translation, 50% rotation |
| Circle button | Reset odometry to (0,0,0) |

The rotation input is **squared** (`Math.copySign(rot * rot, rot)`) to provide fine control at low speeds while maintaining full speed at the extremes.

## Tuning Guide

### Steer PID (TunerConstants)

Current values: kP=10, kI=0, kD=0

If steer modules oscillate or are slow to reach target angles:
1. Increase kP until the module oscillates
2. Add kD to dampen oscillation
3. Use Tuner X's Plots to visualize steer position vs. target

### Drive PID (TunerConstants)

Current values: kP=0.02, kV=0.124

For closed-loop velocity control in autonomous:
1. Run SysId routines to characterize the drivetrain
2. Set kV from SysId feedforward analysis
3. Tune kP for steady-state error correction

### PathPlanner PID

Translation: P=0.5, I=0, D=0
Rotation: P=0.3, I=0, D=0

Tune these if the robot deviates from planned paths:
- Increase translation P if the robot consistently lags behind the path
- Increase rotation P if the robot's heading doesn't match the planned heading
- Add D if oscillation occurs

### Key Swerve Request Types

| Request | Description | Used In |
|---------|-------------|---------|
| `FieldCentric` | Drive relative to field (forward = downfield) | Teleop driving |
| `RobotCentric` | Drive relative to robot (forward = robot front) | Not used |
| `ApplyRobotSpeeds` | Apply a ChassisSpeeds directly | PathPlanner autonomous |
| `SysIdSwerveSteerGains` | System identification for steer motors | SysId routines |
